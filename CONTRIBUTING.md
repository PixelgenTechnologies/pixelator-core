# Contributing

## Pull requests

Open pull requests against `dev`. They are **squash-merged**, and the **PR title becomes the commit message**.
Releases are generated from these messages, so the title must follow
[Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<optional scope>): <description>
```

| Type | Use for | Version bump | In changelog |
| --- | --- | --- | --- |
| `feat` | New feature | minor | yes |
| `fix` | Bug fix | patch | yes |
| `perf` | Performance improvement | patch | yes |
| `revert` | Revert a previous change | patch | yes |
| `refactor`, `docs`, `test`, `build`, `ci`, `chore` | No user-facing change | none | no |

- Mark a breaking change with `!` (`feat!: drop Python 3.11`) or a `BREAKING CHANGE:` footer. This bumps the major version.
- Keep the description short and in the imperative mood (`fix(graph): handle empty components`).
- A CI check validates the title of every PR.

## Changelog and releases

Do **not** edit `CHANGELOG.md` or bump any version in a PR. Both are generated by
[release-please](https://github.com/googleapis/release-please), which keeps a release PR open on `dev`.
Merging that PR creates the tag and the GitHub Release, which publishes the wheels.
